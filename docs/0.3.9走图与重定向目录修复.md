# 0.3.9 走图与重定向目录修复

本版处理三个反馈：方向键到边缘后再次按键不切图、地图中心被占时走不过去、虚拟机备份把目录或虚拟文件判为不可使用。

## 实际出口与中心空位

旧逻辑把出口固定为地图最外一格，并只调用普通移动。该操作不能代替人物已经站在实际出口格上时的切图处理。本版读取当前场景 `o_tile_transition` 的格子与向外方向，限定为人物当前行/列的邻近出口。到达前重新检查场景、人物、敌人、受伤、前台与菜单状态。

已经站在出口格上时，调用游戏 `scr_playerTileborderTransition` 原版入口，不再发送零距离寻路。向出口移动完成后，如场景尚未变化，只补发一次原版出口处理；未切图则停止，不反复触发，不直接修改房间、坐标或地图状态。没有实际出口、方向不符或出口不可达时停止。

中心键先检测单位占用，并使用游戏原版路径查询确认可达。中心不可用时，在中心向四周各 8 格的范围内按到中心的距离排序，等距时优先靠近角色的位置；只对选定位置发起一次移动。每次最多检查 8 个候选，检查批次达到 5 毫秒后让出；整个准备阶段最多 8 秒，单次原版查询本身不可抢占。途中遇敌、受伤、切后台、打开菜单或手动接管时取消。周围无可达空位时停止，不攻击占位单位。

静态核对使用与已适配 SHA256 一致的 Steam 0.9.4.25 / Build 24780451 本地 EXE；研究输出不提交公开仓库。桥接升级为 **v8**，旧桥接必须随游戏正常退出后卸载。

## 重定向与虚拟存储路径

旧引擎把任何 `ReparsePoint` 都当作目录/文件链接拒绝。Windows 的云文件和虚拟存储也使用这种属性；需要通过标签区分。[微软的重解析点标签说明](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-tags) 定义了表示路径替换的 name-surrogate 位。

- 所选存档根目录、备份根目录及其父目录允许明确的目录链接，先解析最终位置，再检查存档和备份不能互相包含。
- 非路径替换的云文件、虚拟存储标签不再当作符号链接；快照通过字节流复制，避免把源文件的链接或云存储元数据带进 ZIP。
- 存档内部的目录链接和文件链接仍拒绝，避免循环和越界；未知标签、解析失败、离线或访问被拒绝仍据实报错。
- 历史列表和还原使用与备份相同的最终目录；已有旧格式 ZIP 继续可用。
- 保留本地压缩与校验、共享目录传输校验、失败时保留已完成本地 ZIP、还原前保险备份等保护。

报错新增版本、失败步骤、异常类型和错误码。存档管理窗口显示版本，并可点击“复制状态与路径”。未获取到用户这次报错的完整原文，以上修复针对代码中已确认的路径误判；不能据此宣称所有 Mac 共享驱动问题已经解决。

## 验证

400 项离线检查：27 项补给原生模拟、172 项交互/走图策略、20 项实际走图适配器模拟、39 项变速意图、95 项托管策略与原有存档检查、39 项兼容性检查、8 项旧存档脚本回归。

新增覆盖四向实际出口、非最外格出口、站在出口上、缺失出口、不重复切图、中心被占、单位占位、最近可达候选、搜索遇敌/耗尽；使用 Windows 实际 junction 目录链接验证备份、历史列表、GUI 子进程还原、逻辑路径还原、根目录别名隔离、内部链接拒绝与外部文件保持原样。

实际解压的自带 .NET 发行程序在独立临时存档上验证；Windows SMB 环回共享验证程序从 UNC 路径运行并向 UNC 目录备份/还原。云/虚拟存储标签是策略测试，不能代替对应驱动实测。

便携验证中独立测试 EXE 创建 junction 被 Windows 拒绝；改用开发环境的 .NET 主机建立测试夹具。实际存档操作仍全部由解压包中的自带 .NET EXE 子进程执行，并通过子进程路径观察确认。子进程 PATH 不含开发工具，PowerShell 环境故意设为不可用；助手本身不创建 junction，也不依赖测试主机。

**本版未启动游戏进行实机验收，未在真实 Mac 虚拟机中实测。** 不操作个人存档；文件校验通过不代表游戏内成功加载存档。升级前先在游戏内保存并正常退出，再退出旧助手、完整解压新版并重新启动。

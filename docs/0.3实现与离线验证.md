# 0.3 实现与离线验证

日期：2026-09-06。延续 0.9.4.25 / Steam Build 24780451 的完整 EXE 与 data.win 哈希适配。用户要求立即开发且不接管电脑，因此没有启动游戏、启动助手界面、发送输入或抓取桌面；已暂停此前凌晨 05:00 的重复执行安排。

后续已获得试机授权，并完成 [0.3.1 实机稳定性测试](0.3.1实机稳定性测试.md)。下文保留 0.3 当时的离线验证范围。

## 单面板

`HudWindow` 替换左右双窗，采用一个非激活置顶窗口。顶部 Thumb 拖动整体，四角 Thumb 独立缩放；坐标以游戏客户区 DIP 保存，拖动用鼠标起点和绝对位移换算，避免窗口跟随鼠标导致相对坐标反馈。四角缩放保持对角锚点，边界限制在客户区内。游戏窗口改变位置时随之平移，布局数据不会每帧重新写盘。

`HudGeometry` 根据可用宽高重新选择按钮行列，窄面板收起文字，保留悬停说明和可见倍率。统计区保留四项数值。设置与存档窗口可滚动；补给开关在设置、右键菜单和按钮边框同步显示。

## 物品常显

区分持久化的 `ShowLabels`、协议中的请求状态、实际施加状态。新增幂等 `HighlightSet` 命令；重新连接、心跳恢复和切换原版面板不会把用户意图改成关闭。

原桥接仅记住自己发送过 Alt 按下，装备界面清空引擎输入时会误以为仍生效。现在通过 `keyboard_check` 读取引擎当前状态，缺失时向游戏原窗口处理器补上按下状态。库存/装备和悬浮信息不再触发常显释放；后台、加载、对话、确认框和心跳失效仍释放。未通过 Windows 全局按键注入持有 Alt。

此修复有代码和原生入口依据，但尚未实机观察“装备栏开关期间标签可见性”。

## 原生补给

桥接保持在游戏窗口线程执行，使用当前场景的实例查询，不缓存跨地图物品指针，不直接修改物品属性或角色状态。每条命令带窗口/地图代际和截止时间，前台、场景、原版 UI 状态及原生可用性检查通过后才执行。自动模式额外检查敌人、伤害、伤势、移动与回合空闲状态。

静态分析记录（均为当前已锁定版本 RVA）：

| 入口 | RVA | 用途 |
|---|---|---|
| scr_can_use_items | 0x697ca0 | 物品原生使用限制 |
| scr_can_use_torch | 0x69ad80 | 火把装备/附着、燃烧时间与角色限制 |
| scr_torch_try_to_equip | 0x71f0d0 | 随身备用火把的原生装备流程 |
| event_perform | 0x51ebd00 | 保留继承上下文执行 Other / 24 |
| o_inv_bottle_water Other_24 | 0x2f415e0 | 原生饮水、扣除次数并进入回合 |
| o_inv_torches Other_24 | 0x2d71df0 | 原生点亮/熄灭并进入回合 |
| keyboard_check | 0x520dde0 | 检查原版输入是否被面板清空 |

data.win OBJT 的父类字段在记录偏移 28：水壶 737、水瓶 9546 继承饮水基类 1690，普通火把 1711 继承火把基类 1136。每类最多扫描 256 个实例；沿 owner 链检查玩家随身物品，排除箱子，循环最多 8 层。

饮水剩余次数来自 `charge`；**普通火把 Create 把 charge 初始化为 -1，火把不能按 charge>0 筛选**。火把使用 `data["Duration"]` 检查剩余燃烧时间，`data["is_fire"]` 判断点亮，`equipped` / `data["isAttached"]` 判断是否实际装备。离线模拟特意使用 charge=-1 的火把，防止误用饮水字段。

饮水优先使用剩余较少且原生允许使用的随身容器；执行后重新取实例检查次数减少。火把优先当前装备/附着的对象，再选备用，通过原生 helper 装备后使用原生事件；动作后回读是否到达目标状态。已点亮时重复“保持点亮”不再次执行事件。不自动装备已经点亮但未装备的对象，避免误熄灭。

自动化默认关闭。主机 `SupplyPolicy` 串行发出操作，切图后至少等待约 2 秒，动作之间至少约 3 秒；原生还有 1.5 秒冷却。饮水仅在数量减少且口渴改善后才允许继续，未确认动作会锁定暂停，需重新开启。手动火把操作关闭自动保持点亮。当前自动火把不推断天气或昼夜。

协议提升至 v3，新增补给可用标志、火把数量/时长和实际常显状态。v1/v2 桥接仍在游戏中时，新版拒绝混用并说明需方便时重启游戏。

## 图形存档管理

现场读取了此前“备份紫色晶石存档”任务及目前的 PowerShell 7 脚本。随包 `Assets/SaveManager/Core.ps1` 复制当前存档核心，原用户脚本保持不变。GUI 通过隐藏的 PowerShell 子进程运行 `Invoke.ps1`，使用参数列表和 JSON 请求文件传递路径，返回结构化结果；不会弹出命令行窗口。

提供完整备份、更新最新副本、历史列表和还原。默认使用原备份目录和 `.manager.lock`，防止图形/命令行管理器竞争。还原须选中具体备份，在图形界面确认；先保险备份、检查 ZIP 路径与哈希、检测并发写入、逐文件安装且元数据后置，失败时回滚，最终比对树签名。操作进行中不允许退出管理窗口或助手，避免中断写入。

此前任务对运行中热还原只证实文件恢复，游戏实际加载曾失败。本版明确区分文件还原与游戏读档；没有宣称热还原加载已修复，也没有写入用户真实存档。

# 晶石助手：便捷功能规划

日期：2026-09-06。状态：需求整理与静态可行性研究；本文新增功能尚未实现、尚未在游戏中验收。现有版本能力见《实现与验证.md》。

开发进展补记：0.2 已实现底部 HUD、倍率保持、生存四项数值和物品常显；实际验证见 [0.2 实现与验证](0.2实现与验证.md)。喝水、火把和五点走图仍待实现，以下保留完整规划。

本次补充：下一版首先解决顶部遮挡、切图丢失所选倍速和工具感过强三个问题。布局以底部原生技能栏为中心，新增功能分布在两侧原版按钮上方的空位。详细设计、当前画面依据、会话恢复规则与验收清单见[游戏界面融合与切图状态保持规划](游戏界面融合与切图状态保持规划.md)。本文此前“主条下方”的状态展示方案由该底部布局替代。

## 体验原则

减少反复开菜单和定位按钮，保留原版行动、回合、物资消耗、装备限制与探索规则。提醒和自动操作仍会降低管理负担，不能声称对难度绝对没有影响。默认采用信息显示与玩家主动触发，自动操作单独开关。

不得根据未被玩家发现的敌人、陷阱、物品或地图内容改变提醒和走图行为。对危险的判断只能使用原版允许玩家获知的状态，不把“目前没有可见敌人”当作安全保证。

## 优先顺序

| 批次 | 功能 | 交付行为 |
| --- | --- | --- |
| 优先修复 | 切图保留所选倍速 | 分离所选倍率与当前生效倍率，过图或同会话重连后恢复选择；明确恢复正常后不再自动加速 |
| 优先改版 | 底部界面融合 | 移除顶部常驻条，左下生存与补给、右下探索与倍速，避让原生按钮和打开的面板 |
| 第一批 | 物品标签常显 | 一键开关，显示原版允许高亮的物品与容器；跟随原版可见性规则 |
| 第一批 | 生存状态条 | 饥饿、口渴、疼痛、迷醉实时数值，异常提醒；可选疲劳、士气、理智 |
| 第一批 | 一键喝水 | 使用玩家指定或明确识别的可用水袋一次，保留原版效果与行动代价 |
| 第二批 | 五点走图 | 正常寻路到本张局部地图的上、下、左、右边缘中点或地图中央 |
| 第二批 | 行走降速与停止 | 可见危险或原版中断时停止辅助行走，恢复 1×，等待玩家决定 |
| 第二批 | 火把快捷操作 | 先实现原生点燃/熄灭；再验证装备与恢复原配置的操作链 |
| 后续可选 | 行走途中自动喝水 | 默认关闭，符合条件时只执行一次，再重新检查状态 |
| 后续可选 | 火把耗尽替换 | 默认关闭，仅原配置兼容且无可见危险时尝试替换，失败停止 |

## 物品标签常显

- 控件：“物品常显：开 / 关”。保留玩家手动切换的能力。
- 优先接入原生高亮显示状态；先核对游戏已有“仅拾取高亮物品”选项及其与高亮切换的关系。
- 不通过操作系统长期按住 Alt 实现，以免影响 Alt+Tab、快捷键、背包交互和其他程序。
- 只显示原版高亮可显示的对象；不枚举并显示迷雾内物品，也不自动拾取。
- 切后台、退出或断连时撤销工具的临时控制；若玩家期间主动修改了设置，不能用旧快照覆盖其修改。
- 验收包含地面物品、容器、树木遮挡、迷雾边界、背包、商店、菜单及 Alt+Tab。

## 生存状态条

左下生存状态簇可折叠显示：`饥饿 --% | 口渴 --% | 疼痛 --% | 迷醉 --% | 水 --次`。具体呈现采用与游戏一致的图标加数字，文字通过悬停提示显示；此处仅描述信息组成，不是界面资产。示例为占位符，不代表当前角色读数。

- “饥渴”拆成饥饿和口渴两个指标；迷醉读取游戏对应数值，不与酒醉效果、毒药效果混用。
- 以原版角色面板显示口径为准。先实测单位、范围、取整和负值语义，再决定显示格式。
- 数字配合文字、图标与颜色，不能仅靠颜色传达严重程度。提醒阈值可配置，默认依照当前版本原版阶段。
- 每次数据采集发布完整快照，界面建议每秒更新 4 次；状态提醒仅跨越阈值或显著变化时触发，避免持续鸣叫。
- 断连、主菜单、读档与角色切换时显示“未读取”，清空旧角色快照，不将无数据渲染为 0。
- 可增加疲劳、士气、理智、装备耐久、水量和火把剩余量；只展示经过实际验证且玩家原本可查询的信息。
- 阈值和变化箭头只用于提醒，不自动选药、吃食物或处理疼痛。

## 五点走图

“移动”指角色沿原生路径逐格行走，与现有“镜头居中”分别命名和显示。

- 方向盘：上方中点、下方中点、左侧中点、右侧中点、地图中央。快捷键可绑定，不默认占用原版单键移动键。
- 首版限定规则清楚的户外局部地图。目标使用可行走网格和合法边界，不能简单拿画面像素宽高计算。
- 默认到边界内侧合法格停下；另设“到达后跨图一次”选项，关闭为默认。跨图完成立即结束本次命令，不连续穿越多张地图。
- 几何目标被已知障碍挡住时，在小范围内寻找可达替代格，并显示实际目标；不可达则报告失败。
- 原版若不允许直接向未知区域寻路，则遵守该限制；不读取未探索地形来计算最优路线。
- 使用玩家点击地面时同一条原生寻路与行走调用链。不得直接写角色坐标、调用传送或使用过场专用移动函数。
- 保留路径经过的回合、饥渴消耗、遭遇与原版危险处理。速度沿用现有 1×–4×，不改变每回合位移。
- 遇到可见敌人、受伤、新出现的可见危险、原版停止移动、菜单/对话、切后台、断连或换图，取消本次辅助意图，恢复 1×。
- 人工移动、攻击、技能或停止键优先。不得在原版中断后反复提交路径来强迫角色继续。
- 多步动作串行执行：喝水或换火把占用动作时，先暂停走图；动作完成后重新判断，不在同一回合并发提交。
- 验收必须比较手动行走与辅助行走相同路径的格数、回合及资源变化，并覆盖挡路、可见敌人、隐藏敌人出现、陷阱发现、跨图、卡住和中途接管。

## 喝水与火把

一键喝水优先使用玩家指定的普通水袋。无水时提示，不自动替换为酒、药水或其他带额外效果的饮料。每次触发只使用一次，不循环灌水，不直接改口渴值。水袋可以通过原版水井/水桶交互补充，后续可加入“靠近可交互水源时提醒补水”。[官方 Wiki：水袋](https://stoneshard.com/wiki/Waterskin)

自动喝水默认关闭，建议仅作为辅助走图期间的可选行为：达到用户阈值、原版允许行动、无可见危险、没有菜单/对话时，暂停路径、使用一次、重新检查。它会减少生存管理负担，不能当作与手动操作体验完全等价。

火把能点燃并提供照明、消除照明区域内的黑暗惩罚，因此自动开关也会影响探索决策。[官方 Wiki：火把](https://stoneshard.com/wiki/Torch)

分阶段实现火把功能：

1. 一键点燃/熄灭当前可操作火把，保留原生限制与消耗。
2. 一键进入玩家指定的照明装备配置，再一键恢复原配置；实测双手武器、盾牌、武器组、背包空间与火把所在槽位的相互限制。
3. 可选耗尽提醒；确认机制后再增加耗尽替换。涉及冲突、无法恢复或多步动作中断时提示，不擅自选择要卸下的装备或丢弃物品。

不默认“看到敌人自动换最优武器”，不自动喝药、包扎或解除疼痛。这些操作包含战术与资源选择。

## 其他值得做的便捷功能

- 出发补给清单：显示水、食物、绷带、夹板、火把等当前数量，玩家自己定目标数量；不自动购买。
- 快坏食物提醒：按原版可见的新鲜度信息排序，提醒尽早处理；不自动选择吃哪一种。
- 装备耐久提醒：达到阈值只提醒，回城时汇总需要修理的装备。
- 自定义物品保护标记：在助手里标记不想卖/丢的物品。真正拦截出售/丢弃需另行验证原版入口，不能只画标记就宣称防误售。
- 探索笔记：手动标记水源、暂存物资、尚未开启的门与返回目标；不自动揭示未发现地点。
- 两侧增强簇可分别收起，保留小状态图标与倍率数字；支持热键自定义、透明度和锚点微调，提升日常操作舒适度。

## 本机静态研究依据及限制

2026-09-06 对已安装游戏的 EXE 和 data.win 只读检索，未向游戏提交新功能命令。找到以下符号：

| 功能 | 发现的原生名称示例 | 当前证据边界 |
| --- | --- | --- |
| 物品高亮 | `show_highlight_alt`、`show_highlight`、`scr_draw_highlight_loot`、`o_checkbox_pick_only_highlighted` | 证明存在相关逻辑；切换状态变量、选项联动及恢复方式待验证 |
| 生存状态 | `scr_hungercheck`、`scr_thirsty_check`、`scr_paincheck`、`scr_intoxication_check` | 证明存在状态处理；用于显示的实际字段和单位待验证 |
| 玩家寻路 | `scr_grid_path_player`、`scr_player_move`、`scr_player_path_draw` | 证明存在玩家移动链；参数、行动状态与中断契约待验证 |
| 火把 | `scr_can_use_torch`、`scr_torch_try_to_equip`、`scr_torch_on`、`scr_torch_off`、`scr_player_torch_count` | 证明存在火把操作；装备槽位、动作代价与原生前置检查待验证 |
| 喝水 | `o_drink_target` 相关事件 | 仅为饮用交互候选；尚未证明这就是水袋使用入口 |

发现函数名不等于接口已适配。实现时应复用经过验证的原生用户动作入口，不能直接调用名称看似相关的底层效果函数绕过检查和消耗。每项功能单独声明能力，未经验证的按钮不显示“可用”。

在线 Wiki 页面可能落后于本机 0.9.4.25，本文不把旧页面中的数值写死为实现常量。饥饿、口渴、疼痛、迷醉属于角色健康指标的分类参考：[官方 Wiki：属性与状态](https://stoneshard.com/wiki/Attributes)。

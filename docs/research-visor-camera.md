# 面甲快捷操作与局部地图摄像机：研究补充

研究日期：2026-09-05。仅研究和设计，未向运行中的游戏发送键鼠输入，未安装或执行 Mod，未修改游戏或存档。

## 关键判断

1. **面甲已有原生快捷栏入口，应先验证这条最简单的实现路径。** 官方 0.9.4.21 更新明确修复：面甲开/关动作图标放到快捷栏后，经右键菜单调用会重复触发的问题。这是“动作可上快捷栏”的官方证据；不等于已在用户当前角色上验证成功。[官方公告](https://steamcommunity.com/games/625960/announcements/detail/699891910775407295)；[官方新闻聚合中的完整原文](https://steamcommunity.com/app/625960/allnews/?l=english)。
2. **“B → 点击面甲”很可能是打开动作/模式菜单，不是打开背包。** 历史官方 Wiki 控制表将 B 列为模式切换，技能栏支持数字键；该表较旧，不能代替本机绑定读取。[控制表](https://stoneshard.com/wiki/How_to_play_guide_for_Stoneshard)。
3. **摄像机居中和角色移动到中央是两个功能。** 当前需求按“只平移镜头至所在局部场景的几何中心”设计；角色不移动，不揭开战争迷雾，不缩放显示整个地图。作者的 GetMoving Navigation 用小键盘 5 让角色寻路到户外地图中央，不能直接用作本需求的实现。[作者说明](https://www.nexusmods.com/stoneshard/mods/143)。
4. 本机静态研究发现 `gml_Object_o_cameraController_KeyPress_35`（键码对应 End 的候选事件），但**尚无证据证明 End 的实际作用就是地图居中**。它也可能是开发遗留、受开关控制或另一种操作。不得把字符串名称当成可用接口。

## 已知证据与限制

主任务本机只读检查报告：EXE 版本 `0.9.4.25`、Steam build `24780451`；`data.win` 不含 `CODE` 块；EXE 字符串包含：

- `gml_Script_scr_item_helm_toggle_visor`、`gml_Object_o_visor_toggle_Other_12`。
- `scr_cameraAttachToRoom`、`scr_cameraUpdate`、`scr_cameraViewUpdate`、`scr_camera_set_target`。
- `cameraMain`、`cameraWidth`、`cameraHeight`、`centerCamera`、`freeCamera`。
- 设置存在 `[main] return camera=1`；视频设置为 `fullscreenBorderless`，游戏分辨率 2560×1440、显示设备 3840×2160。

这些是存在相关程序构件的证据，尚不是函数调用约定、内存地址、行为或可热补丁性的证明。完整本机原始检查见 `research/local-package-inspection.json`。本补充未独立复测这些数值。

### 面甲

官方 0.9.4.6 “Blood Omens” 增加多数重型头盔的面甲开合并改变装备属性；`Unyielding Defense` 还能关闭装备中头盔的面甲。因此状态不能只靠辅助工具每次按键自增/取反推测：游戏自身动作也可能改变它。[官方更新](https://store.steampowered.com/news/posts/?appids=625960&enddate=1774555931&feed=steam_community_announcements)。

本轮没有找到明确说明面甲开合耗费多少回合的可靠作者/官方材料，也没有实机操作证据。需求应写为“调用原生面甲动作并保持原有回合成本”，实际耗回合量在原型阶段测定；不要直接改装备数据、绕过回合结算或承诺零回合。

### 摄像机

- 官方 0.9.2.8 更新已支持改绑自由摄像机按键。[官方说明](https://store.steampowered.com/news/posts/?appgroupname=Stoneshard&appids=625960&enddate=1745758648&feed=steam_community_announcements)。
- 作者 Immortal127 的 Persistent Turn Skip Camera 明确针对“跳过回合时镜头回到角色”提供修改，并要求 modbranch。它支持“回中角色会覆盖自由视角”的兼容性风险判断，但不是本机 `.25` 已复现的证据。[作者页面](https://www.nexusmods.com/stoneshard/mods/210)。
- NeoConsole 的公开代码中 `scr_neoconsole_devcam.gml` 只切换 `global.devCamera`，以及修改 `global.devCameraSpeed`；文件明确写着依赖原始控制台的全局变量、不能独立使用。其 `NeoConsole.cs` 声明目标版本 `0.8.2.10`。这些只能作为找入口的历史线索，不能直接拿来承诺本机版本支持。[摄像机命令源码](https://raw.githubusercontent.com/Nylux/Stoneshard-NeoConsole/master/Codes/Scripts/Base/scr_neoconsole_devcam.gml)；[版本声明与注册代码](https://github.com/Nylux/Stoneshard-NeoConsole/blob/master/NeoConsole.cs)。
- ShardMaster 作者说明提供 `devcam` 和 `devcamspeed`，证明该方向已有 mod 实践；本轮未获取并核实其当前摄像机实现源码，不把描述当成当前主分支适配证据。[作者页面](https://www.nexusmods.com/stoneshard/mods/46)。

## 面甲操作设计

### 第一优先级：原生动作栏 + 辅助工具按键映射

原型步骤：检查 B 打开的菜单 → 找到面甲图标 → 验证能否拖入空快捷栏槽位 → 记录槽位实际绑定 → 分别以鼠标原生调用和对应键调用进行比较。快捷栏可能分别提供开/关图标，也可能按当前状态变化；具体形式以实机为准。

外部悬浮条可以映射用户自定义键到这个已配置的槽位键，前提为：游戏前台、角色处于可操作场景、用户已完成绑定；每次按下只发一次键下/键上，防止长按重复。热键可重绑并检测冲突，不预占既有 mod 常用 F4。

仅发送原生键时，界面显示“面甲快捷键已配置 / 已发送”，不能假装知道“已打开”。如果快捷栏分页导致同一槽位变成别的技能，则不可盲发：V1 约束固定当前快捷栏，或识别槽位图标和页码；可靠性不足时拒绝执行。

### 第二优先级：经过版本验证的游戏内适配

若需要“单键自动切换 + 实时开/关状态”，实现 `GetVisorState()` 与 `RequestVisorState(desiredState)`：先读当前已装备头盔、可开合能力及状态，再调用原生动作入口；动画/交易/死亡/读档时拒绝或等待到安全帧，完成后由游戏反馈结果。以命令序号去重；换装备或房间后重新查询。

按“设置到打开/关闭”传递命令比跨进程发送裸 `toggle` 更便于去重。若在请求处理前发现角色/头盔实例已变，返回 `stale_equipment`，不要把命令作用到新头盔。

### 鼠标宏作为可选降级

只有原生动作栏路径不成立时才评估 B+点击宏。应基于游戏客户区、UI 缩放和图像锚点定位动作菜单，不硬编码桌面像素；保存并恢复鼠标位置，检测菜单出现，超时中止。2560×1440 游戏画面与 3840×2160 显示设备并不保证同一坐标系。此路线不能天然解决快捷栏之外的状态确认，也容易受本地化、动画和 UI 改动影响。

### 面甲验收

| 场景 | 必须观测 |
|---|---|
| 支持开合的头盔，开与关各多次 | 一次按键只执行一次；原生状态、属性与原生操作一致 |
| 不支持面甲/未装备头盔 | 无动作，明确不可用 |
| 战斗、动画、交易、背包、读档 | 不触发其他技能，不绕过游戏行动条件 |
| 角色自己用技能关闭面甲、换头盔 | 显示状态重新同步，不以工具缓存为准 |
| 快捷栏换页、重绑、键长按 | 不错用技能，不重复发送 |
| 与原生鼠标操作对照 | 记录行动前后回合/状态持续时间/日志，确认成本一致 |

## 局部地图镜头居中设计

### 实现优先顺序

1. 先在安全测试场景验证 End 候选事件和游戏设置里的原生镜头绑定：若已经有该行为，悬浮工具仅映射该键即可，不进入内存适配。
2. 原生键若只是回到角色或无效，评估游戏内小型适配。通过当前地图边界和相机尺寸计算中心，交给现有相机控制器设置目标位置，而非瞬时写一个每帧都会被覆盖的坐标。
3. 无法取得经过验证的当前地图边界/相机接口时，V1 将精确居中显示为“当前版本未支持”。鼠标拖拽到边缘再回拉只能作为校准后的近似功能，不能标为精确居中。

几何计算的设计公式（不是已确认的游戏函数实现）：地图可用范围为 `[left,right] × [top,bottom]`，相机世界视口为 `viewW × viewH`，中心为 `((left+right)/2,(top+bottom)/2)`；若相机 API 用左上角，目标再减半个视口并按边界钳制。不要用角色坐标、世界大地图坐标或固定 `room_width/2` 无条件替代可游玩区域中心。小室内房间、带填充区域的地图以及视口大于房间的情况需要单独分支。

### 行为状态机

- `FollowPlayer`：遵循原游戏相机行为。
- `InspectMapCenter`：一次居中后留给用户查看，可自由拖动；恢复键返回角色。
- `Loading/Transition/Cutscene`：不改变镜头，丢弃过期请求。

“进图后自动居中”作为可选开关，默认关闭。启用时以真正的场景实例/地图切换标识触发，等房间生成、角色和相机都就绪后执行一次；不能仅靠屏幕变黑识别新地图。离开场景、读档、重新连接时清除旧请求。不要持续强制锁住中心与原生摄像机争夺控制。

相机命令至少携带 `commandId`、当前 `sceneId`，结果包含 `applied/unsupported/transitioning/stale_scene`；目标场景不匹配时拒绝，防止一次进图请求延迟作用到下一张地图。

用户若启用“移动时回中角色”，需明确产品行为：居中用于当前观察；后续角色移动可以按原设置回中。若另提供“观察锁定”，要在游戏控制器统一处理，并测试跳过回合、打开菜单、切换地图、剧情移动后的退出规则。

### 摄像机验收

| 场景 | 必须观测 |
|---|---|
| 从东南西北边缘进入户外地图 | 居中位置一致，角色坐标与回合数不变 |
| 小室内、洞穴、地牢、不同大小地图 | 不黑屏、不越界，边界钳制符合预期 |
| 一次居中后移动、跳过回合、开关菜单 | 行为符合“观察/跟随”模式，能可靠返回角色 |
| 连续换图、加载旧存档、剧情场景 | 不对错误场景执行，不打断剧情相机 |
| 1× 至 4×、不同分辨率、缩放与 DPI | 中心不随运行速度或显示缩放漂移 |
| 雾区与已探索区对照 | 仅改镜头，不改变可见性、探索或怪物信息 |

## 本轮没有完成的验证

未确认面甲图标的拖放入口、单槽位还是双槽位、实际回合成本；未确认 End 的行为；未验证当前主分支可调用的相机/面甲函数地址、参数和安全调用时机；未运行任何 mod。这些应列为开发前的技术验证任务，而非在设计中写成既有能力。

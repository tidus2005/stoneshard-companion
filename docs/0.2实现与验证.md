# 晶石助手 0.2：实现与验证

开发与验证日期：2026-09-06。适配基线 Stoneshard 0.9.4.25 / Steam Build 24780451，Windows x64。本次落实底部 HUD、切图倍率保持，并加入生存数值与物品常显。水袋、火把和五点走图仍是后续适配项。

## 已实现

- 两个无激活置顶 WPF 窗口分别锚定游戏客户区底部两侧；深色硬边、SVG 图标、中文悬停提示。中央原版热键栏、生命/能量和底部原版按钮保持原位，顶部不放工具栏。
- 原版菜单状态来自 `o_modificatorsMenu`，对话、确认框与悬停提示另行检测；后台、加载和原版面板期间隐藏窗口及其点击区域。
- 以 PID + 进程启动时间标识游玩会话。`SpeedIntent` 保存用户选择，协议分离 `preferred_multiplier`、实际 `multiplier` 与暂停原因。场景变化只刷新当前状态，不覆盖用户选择。
- 共享连接协议升级为 v2。共享 HWND 与窗口代数在同一 UI 线程重绑定，场景代数由原生相机实例变化驱动；旧窗口或场景的动作请求拒绝执行。命令带过期时间与序号，面甲/镜头动作不自动重试。
- 引擎主线程每 100 ms 根据前台、场景、原版界面和心跳调整实际倍率；主机每 250 ms 回读并协调最新选择。心跳失联恢复 1×，主机的用户选择与当前实际速度相互独立。
- 从 `global.characterDataMap` 读取 Hunger、Thirsty、Pain、Intoxication，逐项验证有效范围，不使用数值为零但不对应健康面板的 `o_player.hunger`。
- 物品常显向游戏原始 WndProc 提供 Alt 状态，仅影响该游戏的输入处理。原版面板、后台、停止或失联时释放；回到游戏恢复开启选择。不使用 Windows 全局长按。
- 修复早期启动连接：引擎帧管理器尚未就绪时不发布半初始化映射，并释放初始化标记以便后续重试。
- 速度控制具有明确的接管/释放状态：可操作地图内接管；进入菜单或失联时恢复一次并释放。启动和主菜单不持续写入游戏步进，保留游戏自身菜单计时。
- 设置提供尺寸、垂直偏移、进图镜头居中、下次游戏沿用倍率；原子保存 JSON。托盘保留设置、隐藏、停止与退出入口。

## 本机验证

开发测试仅运行独立复制的 `TestGame`，存档目录为 `ShardTest0`。正式 Steam 安装和 `StoneShard` 存档未写入。

| 检查 | 实际结果 |
|---|---|
| 构建 | 原生桥接、Probe、WPF 发布构建成功 |
| 意图逻辑 | 39 个断言通过；覆盖同会话保留、新选择覆盖旧选择、主动停止、新进程默认及可选持久化。这是逻辑检查，不是 39 次游戏切图 |
| 原生功能回归 | 14 个检查通过：可用场景、控制器互斥、四档速度、拒绝非法档位、相机居中及位置保持、回到角色、面甲可用与往返、失联恢复 |
| 真实步进 | 两轮回归接近 40、80、120、160 步/秒，每档约 2 秒采样；最终轮原始结果保存在 verification-v02.json |
| 跨地图 | 营地→森林 3×、森林→营地 2×、营地→森林 4×，场景代数 1→2→3→4，所选与实际倍率均保持，窗口代数未变化，没有重复注入 |
| 背包 | 3× 打开原版背包：实际 1×、所选 3×，两组 HUD 隐藏；关闭后恢复 3×、HUD 及常显 |
| 后台 | 前台 3×→后台实际 1×/所选 3×→前台 3× |
| 数值 | 桥接读到饥饿 17.9192、口渴 6.1、疼痛 0、迷醉 0；原版健康面板显示 18%、6%、0%、0%，吻合整数显示 |
| 物品常显 | 标签在原版地图上实际出现，正常行走和上述三次跨图后仍开启，停止后消失 |
| 倍率菜单 | 发布版点击 3× 后游戏回读 preferred=3、multiplier=3、target=120 |
| 先开助手再开游戏 | 最终发布版在引擎早期两次返回尚未初始化，约 3 秒后自动连接；启动画面、主菜单点击与继续读档均正常，进图 ready=1、sceneReady=1。随后 3×→打开背包 1×/所选 3×→关闭恢复 3× |

开发回归原始输出在本机 `artifacts/verification-v02.json`；连续只读观察在 `artifacts/lifecycle-v02.jsonl`。这些临时诊断不作为发行包内容。截图记录在本文相邻 `assets/hud-v02/`。

## 验证边界

- 实测为本机 2560×1440 的游戏捕获画面、150% Windows DPI；尚未完成多显示器不同 DPI、1080p、超宽屏和独占全屏的完整矩阵。
- 真实切图当前覆盖营地与相邻森林，尚未覆盖建筑/地牢楼层连续十次、读档过程中每种弹窗或完整战斗流程。
- 已实现 HWND 销毁后重新绑定；此次地图切换没有实际重建 Windows 窗口，不能将这些切图结果算作 HWND 重建验收。
- 菜单检测覆盖已识别控制器字段；背包与角色面板已实际观察，其他界面组合仍需逐项实测。
- SVG 图标借用 Game-icons.net 授权素材，与原版色调及按钮位置协调；并非官方游戏资源，也不是直接改写游戏自身的 HUD 渲染。

## 后续开发顺序

1. 一键喝水：识别可饮用容器，调用原生饮用操作，回读剩余次数；无容器、空容器或战斗限制时拒绝。
2. 火把：先完成手动切换与真实装备状态，再加入耗尽/进出室内的可选提醒和自动逻辑。
3. 五点走图：地图四边中点和中央，以原生寻路完成；遇敌、受伤、交互或用户输入即停止，不揭开迷雾、不瞬移。
4. 扩大窗口、界面、地牢及重连接验收矩阵，再考虑疲劳、士气和补给提醒。

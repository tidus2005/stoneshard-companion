# 0.3.10：Parallels 共享目录备份修复

修复 Windows ARM64 虚拟机中，文档目录经 `C:\Mac\Home` 指向 `\\psf\Home` 时备份路径解析错误的问题。

在本机 .NET 8 x64 实测，旧版 `Directory.ResolveLinkTarget(path, true)` 将最终网络目标变成当前工作目录下的 `UNC\psf\Home`，导致备份失败或落入错误目录。新版逐跳读取链接目标，保留 UNC 根，再解析剩余路径；最多解析 40 跳，循环链接明确报错。存档内部链接拒绝、完整性校验、保险备份和传输失败后的本地副本保护继续保留。

新增可独立运行的路径回归检查：

```powershell
dotnet src/Probe/bin/Release/net8.0-windows/StoneshardCompanion.Probe.dll SavePathTest 'C:\Mac\Home\Documents' '\\psf\Home\Documents'
```

可在最后追加解压后的 `StoneshardCompanion.exe` 路径，验证发行程序的存档子进程。检查仅创建并清理带随机名称的临时存档与共享备份目录，不读取或修改个人存档。链式链接和循环链接测试已加入常规离线检查。

本次在真实 Parallels 共享目录验证备份、最新副本、SHA256、历史列表和带保险备份的还原，打包后的自带运行时程序也通过相同检查。完整离线检查 402 项通过（原有 400 项加链式链接、循环链接两项），构建零警告、零错误。未进行游戏内加载验收；发行包仍为 Windows x64，在当前 Windows ARM64 上通过兼容运行验证。

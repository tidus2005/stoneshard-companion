# 晶石助手：游戏界面融合与切图状态保持规划

日期：2026-09-06。交付阶段：详细规划，未修改运行程序、未声称故障已修复。本文补充并调整《下一版功能规划.md》的优先级与界面布局，取代旧设计中的顶部常驻工具条。

开发进展补记：同日已开发 0.2，落实底部布局、倍率意图保持、生存数值和物品常显。实际验收与未覆盖范围见 [0.2 实现与验证](0.2实现与验证.md)。本文正文保留规划时的事实与目标，不代表所有规划项均已实现。

## 1. 目标与本次结论

把新增能力组织成原版底部界面的自然延伸：顶部状态区完整露出，中央技能栏保持熟悉的位置与操作方式，左下管理角色状态与补给，右下管理探索、视角和倍速。游戏中减少品牌标题、连接文字和长按钮，真实状态、错误原因与快捷键仍能查到。

切图应被视为同一次游玩的场景变化。玩家选择 3× 后，过图、进入建筑、离开地牢或短暂重新建立连接，均不能悄悄把这个选择改成 1×。临时以正常速度运行与玩家主动选择正常速度必须区分。

优先级：先实现并验证倍速意图保持与会话恢复，再完成底部布局与皮肤，再接入上一份规划中的状态显示、物品常显、喝水、火把和走图。

## 3. 底部功能分区

### 3.1 不占用原生控制区

保护区包括：顶部状态效果、中央血量/能量/技能槽、左右最底部功能按钮、技能提示、物品提示、对话和菜单。新增控件不得覆盖其可点击区域，装饰也不能遮住关键数字。

在本次 2560×1440 截图上，首轮布局候选为：

| 区域 | 近似候选范围 | 内容 | 约束 |
| --- | --- | --- | --- |
| 左下增强簇 | x=150–510，y=1140–1270 | 生存数值、喝水、火把、面甲 | 位于左侧原版按钮上方，避开中央血量框 |
| 右下增强簇 | x=2070–2420，y=1130–1270 | 五点走图、视角、物品常显、倍速 | 位于右侧原版按钮上方，避开中央能量框 |
| 中央 | 原版技能区 | 保持原版所有操作 | 不增加第二条长工具栏 |
| 设置入口 | 右侧增强簇边缘的小徽记 | 布局、按键、自动功能和诊断 | 常规游玩不展示连接日志 |

这些只是根据当前画面选择的初始槽位。最终定位根据游戏客户区、GUI 缩放和原版控件边界计算；窄窗口空间不足时折叠次要功能，不能缩小到难以点击或挤入技能栏。

### 3.2 左侧：角色状态与随身操作

上排显示四个状态图标及百分比：饥饿、口渴、疼痛、迷醉。必要时采用两行两列，数字不省略。状态图标仅负责查看详情，避免点数值时误喝水。

下排为水袋、火把、面甲。水袋角标显示剩余使用次数；火把图标有点燃/熄灭及耗尽状态；面甲有打开/关闭两种形态。点击触发一次原生操作，成功后以游戏回读结果更新，等待期间禁止重复触发。自动功能的开关放在设置页，不能把单击和自动启用混用。

疲劳、士气、理智、补给清单放入展开区。默认界面先保证四个必需指标清晰，不把所有属性做成常驻仪表盘。

### 3.3 右侧：探索与节奏

- 五点走图采用小型方向盘，四个方向表示地图边缘中点，中央表示“角色走到地图中央”。停止动作有独立控件，不能占用中央目标按钮。
- 视角操作与角色移动分组。镜头使用取景框/目标标记图形，走图使用足迹和方向图形；工具提示明确写出“仅移动镜头”或“角色正常寻路”。
- 物品常显采用物品轮廓配眼睛图标，开启时增加边框或角标，避免只有颜色变化。
- 倍速使用紧凑的节奏图标加 `3×` 等数字徽记。点击展开四档选择，点选后收起；保留已有热键。不要用无数字的几个箭头代替倍率，也不要让滚轮划过就改变速度。
- 当前实际运行倍率与所选倍率不一致时，徽记进入暂停/等待样式，悬停显示原因。游戏未确认恢复前，不能显示为已经恢复。

### 3.4 文字、图标与状态反馈

| 原界面文字 | 常驻呈现 | 悬停提示示例 |
| --- | --- | --- |
| 面甲 | 可开合头盔图标 | 面甲已关闭；点击打开；快捷键 |
| 一键喝水 | 水袋图标与次数 | 饮用一次；剩余次数；快捷键 |
| 火把 | 点燃/熄灭火把 | 当前状态；点击将执行的动作 |
| 地图中心 | 取景框图形 | 镜头移到地图中心，角色不移动 |
| 回到角色 | 取景框内角色 | 恢复角色跟随视角 |
| 五点走图 | 足迹与方向盘 | 走向北侧中点；保留正常行走消耗 |
| 物品常显 | 物品轮廓与眼睛 | 显示原版可见物品标签 |
| 恢复正常 | 停止/复位图形 | 停止辅助操作并恢复 1×；快捷键 |
| 连接、版本、错误 | 设置入口的状态角标 | 暂时等待地图、需要检查连接等 |

以上是图标的语义规格，不使用 Emoji 作为最终美术素材。复杂行为在悬停约 350 毫秒后显示短说明与快捷键。禁用原因可查看；数字和关键异常仍保留文字。提供“显示短标签”选项，照顾首次使用和图标辨识困难的玩家。

## 4. 视觉与交互风格

- 以实际技能槽的硬边像素描边、暗石色底、冷灰紫金属边缘为参照。减少大圆角、亮紫色整片按钮和软件式标题栏。
- 新按钮与邻近原版按钮协调，但尺寸不机械等同大技能格。建议命中区先按 32–40 DIP 起步，视觉图形略小，再用实际分辨率验证；高 DPI 下仍须清晰可点。
- 采用有限色阶和一致光源，不加玻璃模糊、霓虹外发光或明显浮动动画。选中时边框与角标变化，危险时短暂强调，平时保持安静。
- 中文说明使用清晰字体，不为了像素感把文字变成难以阅读的点阵。数字对齐，不因百分比位数变化推动相邻按钮。
- 最终图标优先在合法本地使用范围内参照原版对应物品/状态的图形语义，或制作风格一致的新资产；不直接把不完整截图裁成按钮，也不把整套游戏素材打包分发。
- 新界面不常驻“晶石助手”大标题。名称、版本和技术诊断放在设置中，保持工具来源明确但不干扰游玩。
- 两侧可分别收起。正常游玩跟随游戏窗口；切换其他程序或游戏最小化时全部隐藏。透明空位、装饰和非交互状态显示应允许鼠标穿透。
- 原版弹窗和悬停说明优先。无法可靠判断其占位时，先整体隐藏增强簇；不要自作主张把原版控件挪位。

## 5. 切图与倍速保持

### 5.1 已确认的实现缺口

1. `MainWindow.xaml.cs` 的 `PlaceWindow` 将窗口固定到显示器顶部 10 像素处，并未锚定游戏底部 GUI。
2. `SelectSpeed` 只使用遥测中的当前倍率；窗口类没有独立的“玩家选定倍率”字段。
3. 失去前台时发送 `Suspend`，原生模块会恢复基准速度；返回前台没有对应的恢复所选倍率流程。
4. 原生看门狗在助手心跳失效或游戏不在前台时恢复基准速度。这个恢复行为合理，但不应覆盖玩家偏好。
5. 重新连接只发送 `Refresh`，没有重放“设置为所选倍率”的流程；当前代码也没有完整的自动重连状态机。
6. 窗口销毁会令原生桥接的 `ready=0`；现有 `BridgeStart` 的一次性 `started` 判断没有完整支持同进程换 HWND 后重绑。若实际故障属于此分支，只加倍率记忆仍不够。

候选触发原因包括：短暂焦点变化、窗口重建、场景对象暂时不存在、引擎切图时重设速度、真实连接失效。应记录单调时钟、进程与启动时间、窗口代次、场景代次、前台归属、桥接就绪、遥测新鲜度、所选倍率/实际目标速度、暂停原因和命令回执，逐一排除。不能只延长超时或反复注入来掩盖问题。

### 5.2 需要分开的状态

| 状态 | 含义 | 是否允许被临时暂停覆盖 |
| --- | --- | --- |
| 所选倍率 `PreferredMultiplier` | 玩家最后明确选择的 1、2、3、4 | 不允许 |
| 原版基准速度 `BaselineSpeed` | 当前适配版本经过验证的正常引擎速度 | 不允许以已加速速度重新采样 |
| 当前目标速度 `ObservedTargetSpeed` | 游戏现在实际设置的目标帧速 | 可以变化，不能反写成玩家偏好 |
| 场景阶段 | 菜单、加载、可操作地图、死亡等 | 独立于进程是否连接 |
| 连接状态 | 无游戏、连接中、已连接、恢复中、失败 | 独立于场景是否有角色/镜头 |
| 暂停原因集合 | 后台、切图、危险、菜单、用户停止、连接恢复等 | 各自解除，不能解除一种就清空所有原因 |

设置为目标倍率是幂等命令，可以在明确重建后的会话中对齐。面甲切换、喝水和移动属于动作命令，不得在重连时自动重放。

### 5.3 玩家可感知的行为契约

| 场景 | 临时行为 | 恢复条件 |
| --- | --- | --- |
| 选择 3× 后切换地图 | 保留选择；加载中等待，必要时暂时 1× | 新地图可操作、遥测新鲜、没有其他暂停原因后恢复 3× |
| 同进程连接暂时中断 | 隐藏失效控件，保留偏好；原生端按看门狗回落 | 校验同一进程/启动时间，重建桥接并确认后恢复 |
| 游戏窗口重建 | 使旧 HWND 及旧命令失效 | 对新窗口重新绑定，禁止旧请求迟到执行 |
| Alt+Tab 到其他程序 | 隐藏界面，临时 1× | 游戏重新处于前台且可操作后恢复所选倍率 |
| 打开背包、菜单、对话 | 增强簇避让，临时状态不改偏好 | 关闭后依据剩余暂停原因决定是否恢复 |
| 玩家明确选 1× | 保存新偏好为 1× | 切图后仍为 1× |
| 玩家按“停止并恢复正常” | 取消走图/动作队列、偏好设为 1×，恢复实际速度 | 后续切图/重连不自动加速 |
| 可见危险触发保护 | 停止自动操作并回到 1×；可保留原偏好用于展示 | 默认等玩家主动恢复，不自动判断战斗结束并再次加速 |
| 助手退出或崩溃 | 原生端失联后回落；不自行恢复 | 新助手建立有效控制租约后才考虑偏好 |
| 游戏重启 | 保留界面偏好，重新做版本和进程校验 | “下次启动沿用倍率”单独配置；默认先正常速度 |

明确区分目标倍率与实际性能：`3×` 表示已确认的目标设定，不等于在任何负载下都跑到严格三倍。[GameMaker 官方速度接口](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/General_Game_Control/game_set_speed.htm)

### 5.4 恢复顺序与防止旧命令回放

1. 识别同一游戏进程和启动时间，必要时验证文件版本；普通房间变化不重新做整包校验或重复加载 DLL。
2. 新窗口出现时重新绑定窗口消息和原生计时器，保留进程级基准；失败时明确进入恢复失败状态。
3. 取得新的桥接代次、场景代次和足够新鲜的遥测。角色/镜头短暂不存在应报告加载中，不能直接显示断开。
4. 在游戏主线程安全时机确认场景可操作；稳定观察窗口可以采用数次连续采样，但不能仅依赖固定睡眠判断加载完成。
5. 检查所有暂停原因，取最新偏好版本，发送一次绝对速度设置命令。
6. 收到回执并读回目标速度后，更新徽记为生效。恢复期间若玩家改为 2×，之前排队的 3× 请求应失效。
7. 超时仅对幂等设置在确认新连接代次后有限重试；动作命令超时报告未知，不自动补发。

桥接增加引擎端更新时间/心跳，避免只读到一份仍可访问的共享内存就认为连接健康。后台回落不删除偏好，持续有其他暂停原因时不得提前恢复。原生防失联恢复保留，与宿主偏好存储分开。

## 6. 实现方案与边界

### 第一阶段：延用当前架构，拆成两个底部增强窗口

使用现有 WPF 与原生桥接基础，主进程负责会话和设置，显示层拆为左状态/补给簇、右探索/倍速簇和按需出现的设置页。先减少改动范围，验证可用性与外观一致性。

- 位置计算以游戏客户区和 GUI 锚点为基准，明确物理屏幕坐标、截图参考坐标、游戏 GUI 坐标与 WPF DIP 的转换。
- 数据只读状态层与按钮层分开管理命中区域；空白区域不能拦截地面移动或技能点击。Windows 分层窗口支持透明绘制，但实际穿透需要按区域验证，不能以“背景透明”代替点击验收。[Microsoft 窗口说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)
- 不抢焦点，游戏热键按前台与菜单状态启停。处理输入法、快捷键组合键释放以及点击提示框后的焦点恢复。
- 分辨率或 DPI 改变时重新计算布局；两侧可用宽度不足则隐藏次要控件到展开页。保留恢复布局入口。
- 设置只保存偏好和相对锚点，不保存进程指针、HWND、角色对象地址或待执行动作。

### 第二阶段评估：需要更深融合时使用原生 GUI 绘制

若 WPF 外部窗口无法可靠跟随原版弹窗层级、缩放或字体，可研究在 GameMaker GUI 绘制层生成增强控件，由现有宿主管理偏好和诊断。这有机会使视觉、光栅化和菜单遮挡更一致，但需要新增并验证绘制、命中检测和生命周期适配，不能在本轮承诺已具备。

两条路线使用同一状态模型和命令协议，避免界面更换后再次出现倍率记忆问题。先交付可验证的底部融合，是否转原生渲染由实际遮挡、像素风格和输入验收决定。

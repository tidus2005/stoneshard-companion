# 0.3.7 存档兼容性修复

## 问题与范围

用户在 Mac 上的 Windows 虚拟机中，一键备份报 `Microsoft.PowerShell.Utility` 无法加载、`ConvertTo-Json` 不可用。截图能确认 PowerShell 模块加载失败，但不能仅凭截图确定是解压不完整、模块搜索路径、共享目录还是虚拟机架构导致。旧版异常出口再次调用同一 JSON 模块，使原始错误被“存档组件未返回结果”覆盖。

0.3.7 从图形程序中移除了整条 PowerShell 调用链。备份与还原在助手本身的无窗口子进程中运行，使用随包 .NET 的文件、ZIP、SHA256 和 JSON API；不查询 PATH，不加载系统模块，不改变执行策略。原 PowerShell 脚本保留在源码中作为旧备份格式及回归参考，不再随便携版分发。

## 行为与兼容性

- 原默认存档及备份目录保留，兼容旧管理器的带 `StoneShard/` 根目录或不带该根目录的 ZIP，以及旧 SHA256 文件。
- 新增“选择备份目录”，检查所选目录可写并记住选择。原目录的历史备份保持原处，切回即可查看。窗口显示可复制的实际路径，方便识别 Mac 共享文档目录。
- 所有文件路径按字面处理，支持中文、空格、方括号、单引号、分号和超过 260 字符的存档路径。无需拼接 shell 命令。
- 备份先确认源文件稳定，再压缩、解压及逐文件比对，成功后发布历史 ZIP 和 SHA256。刷新最新副本仍保留历史文件。
- 与旧命令行管理器沿用 `.manager.lock` 文件锁；还原前检查两次静止状态、建立保险备份、保留同盘回退材料，使用逐文件替换，保留存档目录身份。
- 拒绝损坏校验文件、目录穿越、大小写冲突、Windows 设备别名、备用数据流和 ZIP 符号链接；设置条目数与解压总量上限。共享文件系统必须支持可读写访问与可靠文件锁，失败时报告，不跳过校验强行覆盖。

该版本仍是 **Windows x64** 应用，不是 macOS 原生工具。Windows ARM 虚拟机通过系统的 x64 兼容运行能力运行；没有在用户的虚拟机验证。游戏桥接、适配版本和 v7 协议不变。备份只保护已落盘文件，不强制游戏保存，文件还原成功不等同于游戏内读档成功。

## 验证

`scripts/test-offline.ps1` 执行原 333 项检查及新增 20 项存档兼容性检查，共 353 项。新检查覆盖异常 ZIP、空校验文件、保留长度及时间戳的并发改写、旧无校验文件 ZIP、完整目录删除后的恢复、持有目录句柄期间的还原、长路径和隐藏文件。

`scripts/test-portable.ps1` 从最终 ZIP 解压到带中文、空格、方括号、`&`、`#`、分号的目录，将子进程 PATH 限制为 System32，并提供无效的 PSHOME / PSModulePath，调用**包内实际 StoneshardCompanion.exe** 的存档入口执行备份与还原。逐文件校验 ZIP，观察实际子进程，确认只使用随包应用存档组件，无需 PowerShell。

所有检查仅操作独立临时存档，不操作个人存档，不启动或控制游戏。发布流程在 GitHub Windows 构建机重复执行上述检查；实际 Mac 虚拟机、共享盘断线场景及游戏内读档仍需对应环境验收。
